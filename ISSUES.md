## 🐞 Баги

### [BUG-0001] High · Ошибка диффа для файла, удалённого и в MR, и в master
MR закрыт, но определяется некорректно, и файл удалён в обеих ветках → попытка загрузить из master падает с 404, дифф не строится.
- MR: https://gitlab.example.com/example-group/example-service/-/merge_requests/3082/diffs#b0f241e6a57a97ab996588742c2f9197941f9250 (файл `assignMeetingTasks.bpmn`)
- Симптомы: лог `MR is not merged. Target commit id is target branch name: master`; затем:
  ```
  404 (Not Found) — loading mr bpmn xml
  404 (Not Found) — showing branch bpmn xml file
  Uncaught (in promise) Error: branchBpmnXml is undefined
      at requireDefined (utils.js:56:15)
      at showBpmnBranch (bpmn-differ.js:582:5)
      at showBpmnDiff (bpmn-differ.js:2007:15)
  ```
- Связано с задачей про удалённые/новые схемы (см. UX).

### [BUG-0002] High · Не находим target-версию при переименовании файла схемы
Схему переименовали — в master такого имени нет, дифф не строится.
- MR: https://gitlab.example.com/example-group/example-service/-/merge_requests/4119/diffs?commit_id=a34a768619d0efd47a331ea94df3653cd0c9dfde#aaaf91f17e455f9dd71767bf9d2c5ac5d5df2350

### [BUG-0003] High · Кнопка BPMN Diff не отображается на части страниц
Найти и устранить проблемы детектирования подходящих страниц GitLab; добавить диагностику причин скрытия.
- Частный случай: при снятой галке **«Show one file at a time»** GitLab показывает все файлы подряд, плагин не понимает, что выбран bpmn/dmn → кнопки нет. Нужно рисовать кнопку сразу ко всем блокам bpmn/dmn-файлов.
- Исходный баг: https://chat.example.com/example/pl/hzu9eoc44384xq4jk6a1apna8a

### [BUG-0004] Medium · Не все строки DMN отображаются
В большую dmn-таблицу добавили снизу 4 строки — часть режимов зума показывает только 3 последние.
- MR: https://gitlab.example.com/example-group/example-adapter/-/merge_requests/775/diffs#747aeb319c37e4c2379be395ca41f33cd784ec42

### [BUG-0005] Medium · Chrome блокирует открытие вкладки при первом Dive-in (CallActivity)
При первом клике по «Dive in» bpmn-файлы грузятся долго и асинхронно, поэтому Chrome блокирует открытие новой вкладки. На последующих кликах (данные уже в кеше) — всё ок.
- Нужно: (1) починить блокировку — заранее асинхронно грузить файлы (может не помочь — возможна перезагрузка, см. `loadProjectBpmnFiles`) или повторно слать событие после загрузки; (2) кэшировать загруженные данные в БД Chrome, чтобы не грузить их на каждой вкладке.
- Код: `call-activity-navigator.js` (обработчик Dive-in, флаг `dataWillBeLoaded`).

### [BUG-0006] Medium · CallActivity: файл вызываемого процесса не находится по processId
По `processId` не всегда резолвится BPMN-файл (`FactoringReject` и подобные). Само «проваливание» работает, баг — в резолве.
- Лог: `cannot find bpmn file path by process id: FactoringReject` (`process-file-index.js`).

### [BUG-0007] Medium · Поиск в диффере работает не везде
Внутренний поиск bpmn-moddle (Ctrl/Cmd+F) на Win10 перехватывается поиском Chrome.
- Не работает на Windows при русской раскладке — баг bpmn-io: https://github.com/bpmn-io/bpmn-js/issues/1888
- Воркэраунд: перед Ctrl+F переключиться на англ. раскладку.
- Нужно: на вкладке диффера всегда использовать только внутренний поиск.

### [BUG-0008] Medium · Проверить инвалидацию кэша в localStorage
Есть сценарии, когда кэш нужно инвалидировать — пересмотреть логику кэширования.

### [BUG-0009] Low · Не работает Ctrl+C (копирование)
Какой-то обработчик блокирует копирование — вернуть стандартное поведение браузера.

## ✨ Функциональность

### [FEAT-0001] High · Дифф для конкретного коммита в MR
Сейчас для любого коммита MR показывается итоговая версия схемы (берётся последний коммит). Нужно: сравнивать схему выбранного коммита с вышестоящим коммитом этого же MR (а если его нет — с целевой веткой).
- Пример MR: https://gitlab.example.com/example-group/example-service/-/merge_requests/3931/diffs

### [FEAT-0002] High · Дифф для уже замерженных MR
Находить коммиты/версии схем после мержа и строить дифф без открытого активного MR.

### [FEAT-0003] Medium · Подсветка элементов, чьи делегаты изменились
Подсвечивать Service Task и др. элементы, которые по схеме не менялись, но в этом же MR менялась логика их Java/Kotlin-делегата. Должно быть видно и когда параметры элемента тоже менялись (сейчас уже синий от изменения пропертей).
- Варианты: «кнопка» перехода к делегату рядом с элементом / в панели Implementation (выделять, если делегат изменён в этом MR); рамка вокруг элемента; отдельный цвет (конфликт цветов).
- ✅ Сделано для **external task на Kotlin** (ветка `feature/delegate-change-highlight`): на таске с изменённым в MR обработчиком постоянно показывается overlay-плашка «‹/›» в цвете «изменён» (`handler-navigator.js`); изменённость определяется обратным сканом `.kt`-файлов из MR changes API по топику (`handler-locator.js#findChangedHandlers`). Сигнал развязан с синей подсветкой (изменение имени топика в схеме).
- Осталось: **делегаты** (`camunda:class`/`delegateExpression`, ключ — имя класса), **Java**-хендлеры (добавить `.java` в `ExternalTaskHandlerLocator`), **глубокий анализ** — учитывать изменения в транзитивных зависимостях хендлера, а не только в самом файле класса.

### [FEAT-0004] Medium · Открывать вкладку с кодом делегата
По клику на сервис-таску открывать код делегата из текущего выбранного бранча (master или MR). Связано с [FEAT-0003].
- ✅ Сделано для **external task на Kotlin** (ветка `feature/delegate-change-highlight`): клик по overlay-плашке открывает хендлер в новой вкладке. Для изменённого/добавленного в этом MR хендлера — открывается его diff в MR (anchor по SHA-1 пути файла), чтобы видеть изменения; для остальных — код на текущей показанной версии (резолв «топик → файл:строка» через GitLab project blob-search API `handler-locator.js#resolveLocation`, при неудаче — fallback на страницу поиска GitLab). Работает и в MR-, и в branch-режиме.
- Проверено: project blob-search на `gitlab.example.com` доступен (basic search, без Elasticsearch; параметр `ref` работает) — основной путь резолва валиден, fallback на UI-поиск остаётся страховкой. Делегаты/Java — см. [FEAT-0003].

### [FEAT-0005] Medium · Переход к просмотру вызываемой DMN
По аналогии с «проваливанием» в CallActivity — открывать в отдельной вкладке dmn-ку, вызываемую из `Business rule task`.

### [FEAT-0006] Medium · Поиск элемента на схеме

- Встроенный Ctrl+F вьювера ищет только по наименованию элементов. Связано с [BUG-0007].

### [FEAT-0007] Medium · Панель свойств для DMN

### [FEAT-0008] Low · Переход к коммиту текущего бранча

## 🎨 UX и отображение

### [UX-0001] Medium · Условия на Sequence Flow: игнорировать незначимые пробелы
✅ Частично сделано (ветка `fix/backlog-autonomous-fixes`, 2026-06-11): при сравнении `bpmn:conditionExpression` незначимые пробелы/переносы вне строковых литералов игнорируются (`bpmn-xml-comparator.js#normalizeExpression`). Осталось: улучшить читаемость длинных/сложных expression при отображении.
- Пример MR: https://gitlab.example.com/example-group/example-service/-/merge_requests/4335/diffs
  ```
  было:                                   стало:
  ${                                      ${
    ( !execution.hasVariable("skip…") ||    !(execution.hasVariable("skip…") &&
      !skipRelatedSearch )   &&             skipRelatedSearch ) &&
    estates.hasAnyEstate…()               estates.hasAnyEstate…()
  }                                       }
  ```

### [UX-0002] Medium · Подсветка конкретных переменных при изменениях в маппинге
При изменении In/Out mappings сейчас выделяется вся группа в панели свойств. Нужно выделять конкретные добавленные/удалённые/изменённые переменные.

### [UX-0003] Medium · Доработать для удалённых и новых схем
- Схемы нет в MR (удалена): показывать только master, красить красным (всю или внешний блок?), убрать кнопку смены бранча.
- Схемы нет в master (новая): красить зелёным, убрать кнопку смены бранча.
- Для новых схем в таблице изменений показывать список всех элементов.
- Оговорка: вся схема в зелёном/красном выглядит спорно. Связано с [BUG-0001].

### [UX-0004] Medium · Точность семантического сравнения / подсветки свойств
Накопленные edge cases компараторов:
- **Подсвечивать изменение кода ошибки** (`bpmn:error`): сейчас изменение не подсвечивается. Пример: https://gitlab.example.com/example-project/example-repo/-/merge_requests/795. Код: `bpmn-xml-comparator.js` (маппинг свойств → группа `Error`).
- **`failedJobRetryTimeCycle` относится к двум группам**, поддержана одна (маппинг `camunda:failedJobRetryTimeCycle` на `Multi-instance` закомментирован). Код: `bpmn-xml-comparator.js`.
- **Подобрать корректный заголовок группы панели свойств** для `bpmn:startEvent/isInterrupting`. Код: `bpmn-xml-comparator.js`.
- **Сравнивать DMN outputs по id, а не по label** — сейчас по label, т.к. в html нет атрибута id у outputs. Код: `dmn-xml-comparator.js#compareOutputs`.

### [UX-0005] Medium · Зафиксировать высоту таблицы изменений
Независимый скролл панели изменений; исключить смещение при открытии больших панелей свойств.

## 🔧 Рефакторинг

### [REFAC-0001] High · Получать параметры через GitLab MR API; улучшить поиск хеша коммита
Многое сейчас парсится из HTML или подбирается эвристикой — получать через `GET /api/v4/projects/{project}/merge_requests/{mr}/`. Сделать поиск коммита надёжнее (меньше случаев «дифф не построился из-за неверного коммита»).
- Переделать: `getMrCommitId`, `getMrSourceAndTargetBranchName`, `getTargetCommitId`.

### [REFAC-0002] Medium · Упростить и декомпозировать main.js / выделить сервисы
Разделить UI, GitLab API, работу со схемами и диффами; снизить связанность; убрать крупные функции по модулям.

### [REFAC-0003] Low · Выделить отдельный cache manager
✅ Сделано (ветка `fix/backlog-autonomous-fixes`, 2026-06-11): кэш `getTargetCommitId` вынесен в класс `SingleEntryCache` (в том же `gitlab-repo-provider.js` — новый файл потребовал бы правки `manifest.json`). Возможное продолжение: перевести на него кэши `init` и `initMergeRequestInfo`.

### [REFAC-0004] Low · Абстракция платформы хранения кода → поддержка GitHub
Ввести интерфейс поверх GitLab (`GitLabRepositoryProvider` / `GitHubRepositoryProvider`), вынести GitLab-специфику, определить точки расширения. Целевая задача после публикации в Open Source.

### [REFAC-0005] Low · ⚠️ Перевод проекта на TypeScript
Типизация моделей/сервисов для снижения ошибок при рефакторинге.
- **Конфликтует с текущим ограничением проекта** (только vanilla JS, без build-шага). Требует отдельного решения по архитектуре.

### [REFAC-0006] Medium · Переосмыслить нижнюю таблицу изменений
Таблица изменений в футере (`changes-table-view.js`) требует пересмотра — возможно, она вообще не нужна в текущем виде. Решить, что с ней делать (упростить / заменить / убрать), прежде чем наращивать туда новую информацию (например, список изменённых делегатов из [FEAT-0003]).
