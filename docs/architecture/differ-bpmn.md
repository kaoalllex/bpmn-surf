# Key files — BPMN differ

`src/differ/bpmn/` (incl. `edit/`): the BPMN orchestrator, view, comparator, highlighting, search, edit mode. Overview, flows and scopes — [`../architecture.md`](../architecture.md).

| File | Purpose |
|------|-----------|
| `bpmn-differ.js` | `BpmnDiffer` — the BPMN diff orchestrator + bootstrap (message listener) |
| `bpmn-differ-view.js` | `BpmnDifferView` — the DOM of the BPMN differ page (layout, header, footer, buttons). The header is a flex toolbar (`.differ-toolbar`) with `.differ-btn-group` groups (file + download · branch indicator · Switch branch · view · back navigation · panel toggle + feedback · Close); download/zoom/highlight/close are the icons `↓`/`+`/`−`/`⤢`/`☀☼`(toggle)/`✕` (UX-0007), and the bar ends with the properties toggle `◨`/`◧` (the filled half tracks where the panel is) and feedback `💬` (FEAT-0024). In view mode the view group also carries `✎` (open editor, FEAT-0031). In edit mode (FEAT-0031) the right block is one group per job — zoom · colouring · history: `Switch branch` is not rendered, the `☼` highlight toggle becomes a 🖌 "colour the edits" toggle (pressed = on, greyed = off, `⚠` = paused — BUG-0029) in a colouring group that also carries the `EditColorControl` swatches (appended after construction via the `editGroup` getter), and `↶`/`↷` (undo/redo, enabled from the command stack via `setHistoryEnabled`) form their own group. Both modes end in the same group — the properties toggle next to `💬` — so the toggle does not move between them (FEAT-0024). The back-navigation group (`BackNavigator`, FEAT-0023, icon `⤴`) is mounted via `setBackNavigator()` before `build()` and rendered just before that closing pair. The right block is pinned to the edge (`.differ-toolbar-spacer`), `Switch branch` is a separate group at its start (fixed position, not shifted by the branch name length). The properties panel is resizable: between the canvas and `propsCell` there is a `<td>` splitter `.differ-splitter` (drag → width of `propsCell`), the width is clamped by `BpmnDifferView.clampPanelWidth` (unit-tested) and remembered in `localStorage[bpmnDiffer.propsWidth]`; the `◨`/`◧` toggle hides both the panel and the splitter, and carries the action as its `aria-label` since an icon button has no accessible name of its own |
| `bpmn-xml-comparator.js` | `BpmnXmlComparator` — a semantic comparison of two BPMN XMLs. One diff→panel-group table serves both dialects (`camunda:` and `zeebe:` keys never collide; a `zeebe:` element's unprefixed attributes fall back to the element's own row; `zeebe:userTask` is the one empty extension that is not ignored — its presence is the value). Besides the diff groups (`nodeIdToDiffsMap`) and conditions (`nodeIdToConditions`), `compare()` also returns `nodeIdToMappingChanges` (id → Map(list-group name → `[{label, changed}]`)) for per-element highlighting of In/Out mappings and Inputs/Outputs entries, and `subProcessWithChangesIds` — subprocesses not changed themselves but containing an added/removed/changed element at any depth (subprocess children are compared separately, so the subprocess itself never lands in `changedShapeIds`); the differ paints them with the CHANGE stroke only and adds them to the ☼ highlight, keeping them out of the changes table and the properties panel (BUG-0010); edit mode (`EditSession.setMrDiff`) does not show them yet |
| `diff-highlighter.js` | `DiffHighlighter` — coloring diff elements and highlight markers |
| `changes-table-view.js` | `ChangesTableView` — the list of changes in the footer: one row per changed/added/removed element or connection (associations excluded), in document order, with a change badge, a bpmn-font type icon, the name (a connection's ends) with the id, and the changed property groups. The list follows the plane on screen (`root.set`): changes inside a collapsed subprocess on it, however deep, make one "N changes inside" row of that subprocess. A row click selects its element on the shown plane and scrolls to it. The Changed/Added/Removed counters count the rows of the shown plane (a "changes inside" row counts as changed) |
| `properties-panel-highlighter.js` | `PropertiesPanelHighlighter` — highlighting groups in the properties panel, conditions. For list groups (In/Out mappings, Inputs/Outputs), on top of highlighting the group header it additionally colors the specific changed entries (by `nodeIdToMappingChanges` from the comparator, matched by the entry header text): changed→blue, added→green (MR), removed→red (target); if an entry is not matched — only the group highlight remains |
| `properties-group-expander.js` | `PropertiesGroupExpander` (FEAT-0029) — auto-expands (only opens, never collapses) the property-panel groups most relevant to the selected element: axis A = changed groups from the diff (`nodeIdToDiffsMap`), axis B = groups characteristic of the element type via the pure `relevantGroupsForElement` (events keyed on `bo.eventDefinitions`, gateway flows, multi-instance, task implementations, non-empty In/Out/Inputs/Outputs). Detects the open state by the `open` class on the header and finds the header by text via the shared `utils.js#findPropertiesGroupHeader` (also used by the highlighter). A missing group is a silent no-op. Takes the differ's dialect getter: under C8 a service/send task expands "Task definition" (the Zeebe panel has no Implementation group there), a user task "Form", and the non-empty `zeebe:IoMapping` / `zeebe:TaskHeaders` / `zeebe:Properties` their list groups. BPMN only |
| `condition-formatter.js` | `ConditionFormatter` — formatting condition expressions: JUEL splits after `&&` / `\|\|`, FEEL (`=…`, Camunda 8) after the words `and` / `or` (outside string literals and words; `not(` is a call) |
| `canvas-viewport.js` | `CanvasViewport` — pan/zoom/fit of the canvas |
| `element-searcher.js` | `ElementSearcher` — full-text search over BPMN elements (FEAT-0006): builds an index from `elementRegistry` and searches ids by name/id/parameters. `buildSearchText(bo)` recursively gathers all primitive values of a moddle object (condition expression and its variables, In/Out mappings, Inputs/Outputs, delegate/class/topic, calledElement, documentation), but does NOT descend into references to other elements (they have their own `id`), otherwise a container would absorb the text of the whole schema. Unlike the viewer's built-in search (name/id only) |
| `search-panel.js` | `SearchPanel` — the floating search panel of the BPMN differ (FEAT-0006 + BUG-0007). Opens with Ctrl/Cmd+F, matched by `event.code === 'KeyF'` (layout-independent → works on a layout where the built-in search broke) + `preventDefault` suppresses Chrome's native search. Uses `ElementSearcher`, highlights all matches with a `search-match` marker, centers the current one (`canvas.scrollToElement`), selects it (`selection.select` → the properties panel shows its parameters) and marks it `search-match-current`; navigation ◀/▶ (Enter/Shift+Enter), a counter, Esc — close. The index is rebuilt after every import (`rebuildIndex`) |
| `edit-session.js` | `EditSession` (FEAT-0031) — edit-mode lifecycle: baseline, debounced recompute, wiring, dirty/`beforeunload` |
| `edit-diff-painter.js` | `EditDiffPainter` (FEAT-0031) — the display-only marker layer (fill markers, dashed outline for explicitly coloured elements) |
| `edit-color-control.js` | `EditColorControl` (FEAT-0031) — the toolbar swatches → `modeling.setColor`; "Default" clears |
| `edit-color-resolver.js` | `EditColorResolver` (FEAT-0031) — pure: the layer table → `Map<elementId, {diffType, outlineOnly}>` |
| `edit-xml-colorizer.js` | `EditXmlColorizer` (FEAT-0031) — pure: apply that map onto the exported XML string |
