# Key files — shared differ classes and platform seam

`src/differ/shared/` (used by both the BPMN and the DMN differ) and `src/differ/platform/` (the differ-scope `PlatformClient`). Overview, flows and scopes — [`../architecture.md`](../architecture.md).

| File | Purpose |
|------|-----------|
| `differ-params.js` | `DifferParams` — parsing/validation of the differ page's parameters from postMessage (shared by BPMN and DMN). Neutral fields + a `platform` descriptor; `requirePlatformInfo()` (BPMN), `isSourceVersionDefined()`, `rawFileUrl(ref, filePath=this.filePath)`, `toNestedDifferParams(filePath, fileName, extra)` (the nested Call Activity / caller differ; `extra` carries the FEAT-0023 direction hint). `divedInFrom` (`{filePath,fileName}` | null) — the calling diagram we dived in from (its tab is open above us), set only on dive-in (down); enables dive-out to jump straight back up to it. `selectCalledProcessIds` (`string[]` | null) — set on dive-out (up): the opened caller auto-selects its Call Activity that calls one of these process ids, highlighting the call site. `targetFilePath` (defaults to `filePath`) — the path of the target side, differs only when a file is renamed in the MR (BUG-0002); `targetFileName` = basename(`targetFilePath`) — the file name of the target side for the title and download (when renamed ≠ `fileName`). FEAT-0031: `mode` (`'view'` \| `'edit'`, default `'view'`) and `editSide` (`'target'` \| `'source'` \| `null`) — which side an edit tab edits; `editIdentityKey(editSide)` — the key the edit tab for that side will publish, computed before opening it so a second `✎` press focuses it instead of starting a second session; `toEditDifferParams(editSide)` — wire params for an edit tab on the SAME file (unlike `toNestedDifferParams`, keeps `targetFilePath`/`localFileContent`) |
| `diagram-versions.js` | `DiagramVersions` — loading/storing/downloading the diagram versions (shared). `loadBranchXml()` loads the target side by `params.targetFilePath` (may differ from `filePath` on rename, BUG-0002), `loadMrXml()` — by `filePath`. `download(content, branchName, fileName=params.fileName)` — the file name is passed by the side (target → `targetFileName`, source → `fileName`) |
| `branch-indicator.js` | `BranchIndicator` — the label of the displayed version in the header (the branch name or commit message + short id) + a word for the side's role, so it reads without color: target → `Original`, source → `Changed` (in branch-view without a second side the prefix is not shown); colors (shared); `setShownLabel`/`isTargetBranchShown`. `setAbsentLabel(targetSide)` — a dimmed italic label for the side where the file does not exist (UX-0003), keeping `isTargetBranchShown()` correct. Side-specific text: empty source → `file deleted` (removed in the MR), empty target → `file does not exist` (a new file) |
| `diff-type.js` | `DiffType` — diff types with colors (shared by BPMN and DMN) |
| `camunda-dialect.js` | Which Camunda engine the diagrams target (FEAT-0038), shared by BPMN and DMN: `CAMUNDA_DIALECT` (`'c7'` \| `'c8'`), `detectCamundaDialect(...xmls)` (pure, on the XML text: `'c8'` when any document declares `http://camunda.org/schema/zeebe/1.0` or carries `modeler:executionPlatform="Camunda Cloud"`, else `'c7'` — plain BPMN keeps the C7 behaviour), `isFeelExpression(value)` (`=…`), and the called-id accessors `calledProcessId(bo, dialect)` (C7 `bo.calledElement`, C8 the `processId` of the `zeebe:CalledElement` extension) / `calledDecisionId(bo, dialect)` (C7 `bo.decisionRef`, C8 the `decisionId` of `zeebe:CalledDecision`) — explicit dialect, no fallback, so the other dialect's element yields null |
| `differ-loading-overlay.js` | `DifferLoadingOverlay` — a full-screen spinner shown while the differ page renders (UX-0008). Shared by BPMN and DMN: shown in the view's `build()`, hidden in `showCanvas()`; covers the blank tab of a freshly opened (including a nested Call Activity) differ. The long processId→file resolution runs on the source page and is covered there by the badge spinner in `CallActivityNavigator` |
| `differ-empty-state.js` | `DifferEmptyState` — a placeholder inside the canvas cell (shared, UX-0003 / BUG-0001). Unlike the full-screen `DifferLoadingOverlay`, it lives in the canvas cell, so the toolbar stays available. An empty message = a plain cover (switching to a missing side; `dmn-js` has no `clear()`), a non-empty one = centered text (the file is absent in both versions). The views provide `showEmptyState`/`hideEmptyState` |
| `differ-tab-navigator.js` | `DifferTabNavigator` — shared opener-tab navigation (FEAT-0005, extracted from `BpmnDiffer`), used by both orchestrators: `openNestedDiffer(params, fileName)` opens a nested differ tab, picking the differ kind (BPMN vs DMN) by file extension and supplying the resource-href lookup the fresh `about:blank` tab needs (no `chrome.runtime.getURL`); `focusOpenerAndClose()` brings the opener tab forward without reloading it and closes this one (dive out to where we came from); `navigateOpenerTab(url)` navigates the opener tab (BPMN handler navigation). Cross-tab dedup (BUG-0017): `registerTab(identityKey)` joins a `BroadcastChannel` registry and takes a stable identity-derived `window.name`; `focusExistingDifferTab(identityKey)` asks the channel whether any open tab already shows that diagram and, if so, brings it to the front by name instead of opening a duplicate — so `#openDifferForFile` in both orchestrators reuses an open tab no matter how the user got there (the identity key is `DifferParams.identityKey()` = refs + file path + optional `editSide` + mode; `#openDifferForFile` must compute it from the params about to be sent to the nested tab, not from its own, or an edit-mode tab's dive-in/out is never deduplicated — FEAT-0031) |
| `feedback-report.js` | `FeedbackReport` — builds the prefilled GitHub issue the differ toolbar's 💬 button opens (FEAT-0024): title, markdown body (extension version, platform kind + host, page — including edit mode and the side being edited — file + type, the versions, and in edit mode whether the diagram was touched and how its colouring stands — a Compared/Against pair, one `Version` row for a single-version branch view, or a named local file, which are three different things and were once rendered as one) and the `issues/new?template=…&title=…&body=…` URL. Pure — the caller passes the context and the console tail (`ConsoleLog.tail()`) and does the `window.open` itself. The **whole URL** is budgeted under GitHub's ~8 KB 414 limit, so the log goes last inside `<details>` and sheds its oldest debug lines first, marked `… N earlier lines omitted` / `… N debug lines dropped`. Schema/XML content is never included — which needs guarding at the log too, not just at the context: a failed import is reported by moddle-xml as `unparsable content <a raw slice of the document> detected`, so `ConsoleLog.describeImportError` reduces it to the position and the parser's own reason before it is logged (guarded end to end by `differ-feedback-no-schema.spec.js`). Everything the report *does* carry is named in a notice at the end of the body |
| `platform-client.js` | `PlatformClient` — the differ-scope interface (REFAC-0004) for every platform-specific data access the differ page performs; the mirror of the content scope's `RepoProvider` seam. Methods (throw-stubs here): `rawFileUrl(ref, filePath)`, `blobFileUrl(ref, filePath, line?)`, `searchCode(ref, term)` → normalised `{path, line, snippet}[]`, `searchPageUrl(term, ref)`, `prChangedFiles(changeId)` → `{path, oldPath, status}[]`, `prFileDiffUrl(changeId, filePath)` → `Promise<string>` (the human link to one file's diff; the platform owns the anchor scheme). Search hits are normalised so a platform's own JSON never reaches the locators (they gate/classify on the neutral `snippet`) |
| `gitlab-platform-client.js` | `GitLabPlatformClient extends PlatformClient` — holds verbatim the GitLab URL/search/changes construction that used to live inline in `DifferParams` and the locators (`/-/raw/`, `/-/blob/`, `/api/v4/.../search?scope=blobs`, `/-/search`, MR `/changes`, `prFileDiffUrl` = `/-/merge_requests/{iid}/diffs?file_path=…#sha1(path)`), so GitLab behaviour is unchanged. Constructed from the descriptor's `{projectUrl, hostUrl, projectId}`; fetching still goes through the global cookie-session `loadFileContent` (injectable for tests). Auth-aware fetching is deferred to [FEAT-0037] |
| `github-platform-client.js` | `GitHubPlatformClient extends PlatformClient` — content same-origin via `github.com/{o}/{r}/raw/…`; `prChangedFiles` reads the `/pull/{n}/changes` page payload first (`GitHubChangesPayload`), falling back to anonymous `GET pulls/{n}/files` (≤3 pages); `prFileDiffUrl` = `/pull/{n}/files#diff-<sha256(path)>`; `searchCode` asks GitHub's own web search (`{host}/search?q=repo:o/r "term"&type=code`, `accept: application/json`, same origin, session cookie; default branch only) and normalises the hits; signed out, 429, a non-JSON answer or `errors[]` give `[]` and the navigators open `searchPageUrl`. When the search ref is the PR head (`change.headRef`) the PR's changed files are read raw at the head once per differ (≤100 files, no removed or binary files), grepped for the term and put before the web hits, which drop the paths the PR touched. All URLs come from `platform.hostUrl`; REST is `https://api.github.com` on github.com and `{host}/api/v3` elsewhere (GitHub Enterprise) |
| `platform-client-factory.js` | `createPlatformClient(platform, change = {})` — builds the differ-scope client by `platform.kind` (`'gitlab'` → `GitLabPlatformClient`; `'github'` → `GitHubPlatformClient`; default throws); the differ mirror of `repo-provider-factory.js` |
