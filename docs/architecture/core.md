# Key files — core, hosts, extension context, tooling

`src/core/`, `src/hosts/`, `src/background/`, `src/popup/`, and the repo-level `manifest.json`, `libs/`, `scripts/`, `test/`. Overview, flows and scopes — [`../architecture.md`](../architecture.md).

| File | Purpose |
|------|-----------|
| `host-patterns.js` | Pure match-pattern logic for the configurable hosts (FEAT-0033), shared by the SW and the popup: `normalizeHostPattern(input)` → `https://<host>/*` (a bare host, an origin or a pasted MR/PR url; https only, port/path dropped) or `null`; `userOriginsFrom(origins)` → the granted https origins (deduped, sorted) — every one is a site the user chose, none is built in; `needsGitlabComNotice(previousVersion, origins)` → true for an update from < 1.4.0 that lost the gitlab.com grant (the manifest no longer declares it, and whether Chrome keeps the old grant is undocumented); `UNDETECTED_SITES_KEY` (the `chrome.storage.local` key of the unrecognised sites) and `pruneUndetectedSites(hosts, origins)` → the listed hosts still granted |
| `handler-annotations.js` | Which annotations mark a task handler — a C7 external-task handler or a C8 job worker (FEAT-0035, FEAT-0038): `DEFAULT_HANDLER_ANNOTATIONS` (`topic: ['ExternalTaskSubscription', 'JobWorker']`, `className: []`; a list the user already saved is kept as it is), `normalizeHandlerAnnotations(raw)` (drops a leading `@`, keeps only identifier-shaped names so a stored value cannot widen the regex built from it, de-duplicates; a non-array means "not configured" and falls back, an empty array means "switched off" and is kept), `isDefaultHandlerAnnotations`. Loaded in all three scopes, so no `chrome.*` and no DOM |
| `github-changes-payload.js` | `GitHubChangesPayload.read(doc, number)` → `{changes, pull}` \| null — reads the comparison GitHub's React "Files changed" page embeds (`react-app[app-name="repo"]` → `payload.pullRequestsChangesRoute` or `pullRequestsChangesWithRangeRoute` / `pullRequestsLayoutRoute.pullRequest`); null when the payload belongs to another route or PR. Whether the payload shows the URL's selection is checked by `GitHubDomScraper`. Cross-scope: the content provider and `GitHubPlatformClient` |
| `content-scripts.json` | The content scripts' `js` and `css` lists, in load order (critical) — the one place that defines them. The manifest declares no `content_scripts`: the service worker registers this list for every granted origin, and `test/structure/registries.test.js` keeps it in sync with `SCOPE_FILES` |
| `settings.js` | Persistent settings (FEAT-0035): `loadSettings`/`loadHandlerAnnotations`/`saveHandlerAnnotations` over `chrome.storage.sync` (key `settings`: `handlerAnnotations`, `siteKinds`), `loadSiteKinds`/`saveSiteKinds`, `loadUndetectedSites`/`reportUndetectedSite`/`clearUndetectedSite` over `chrome.storage.local`, plus the exchange file — `buildSettingsExport` (format 1, with `siteKinds` for the exported hosts; older files read as `{}`; hosts as bare hostnames, since `normalizeHostPattern` rejects a `*`) and `parseSettingsExport` (validates, normalises, throws with a readable reason). Popup and content script only — the differ page has no `chrome.*` and gets the values through the differ params |
| `service-worker.js` | Keeps the runtime content-script registrations in sync with the granted host permissions (FEAT-0033): one registration (`bpmn-surf-user-hosts`) whose `matches` are the user's origins (no site is built in) and whose `js`/`css` are read from `src/hosts/content-scripts.json`, reconciled on install/update and on every permission change. Sets the toolbar badge `!` while no site is on, while a granted site's type is unknown (`undetectedSites`, pruned to the granted hosts) or the gitlab.com notice (update from < 1.4.0) waits; on such an update records the notice in `chrome.storage.local` |
| `popup/` | The window opened from the extension icon (`popup.html`/`popup.js`/`popup.css`): the installed version, the "Leave feedback" link, the **Sites** list (any site, gitlab.com and github.com included, can be added and removed; a self-hosted site gets a type select Auto/GitLab/GitHub and a hint when it is not recognised; a Home warning lists hosts waiting for a type), the handler annotations (the add fields for annotations and sites suggest known values through a native `<datalist>`: the stock topic annotations not yet listed — `ExternalTaskSubscription`, `JobWorker`, `ZeebeWorker` — and gitlab.com / github.com), the "no site is on" warnings on Home and Sites and the "Turn on gitlab.com" notice |
| `models.js` | DTOs: `FileType`, `ProjectInfo`, `MergeRequestInfo` |
| `utils.js` | DOM, HTTP, XML parsing, script loading, small string helpers |
| `console-log.js` | `ConsoleLog` — the bounded console ring the FEAT-0024 feedback report ships. `install()` proxies `console.debug/info/warn/error` (so library output is caught too) and adds the window `error`/`unhandledrejection` listeners; `tail()` selects what a report carries: the last N entries of any level **plus** every buffered `info`/`warn`/`error`/`uncaught` wherever it sits — except lines logged from `libs/`, since bpmn-js and dmn-js complain about themselves in every session (INFRA-0001). The character budget sheds the narrative before the signals, gaps are marked `… N lines skipped`, and a cycle of identical or of two alternating lines collapses. It also owns what is *safe* to log — `describeImportError` (a failed import's message quotes the document) and `describeDifferParams` (the raw params carry the moddle and the user's local file) — because the ring is what leaves the machine. Its static state is the differ page's one accepted carve-out from the no-global-state rule (docs/conventions.md) |
| `config.js` | Constants (the feedback URL). Loaded in all three scopes: content scripts, the popup, and — since FEAT-0024 — the differ page |
| `manifest.json` | The MV3 manifest. It declares no `content_scripts` and no `host_permissions` (sites are optional permissions, see above); `web_accessible_resources` and the differ-page files in `utils.js#loadScripts` must stay in sync |
| `libs/` | Vendored dist files of external libraries; generated by `npm run sync:libs`, do not edit by hand (see docs/conventions.md) |
| `scripts/sync-libs.js` | Copies library files from `node_modules` into `libs/` by the versions in `package.json` |
| `scripts/mutation-sweep.js` | Mutation sweep: plants artificial bugs in the priority source files to find what the suite fails to notice (see docs/testing.md, [REFAC-0015]) |
| `test/` | Unit tests (`node:test` + jsdom), the layout mirrors `src/` (`src/<path>/x.js` → `test/<path>/x.test.js`): the vm harness `test/support/scope.js` (included as `require('#scope')`), the fixtures `test/fixtures/` — see docs/testing.md |
