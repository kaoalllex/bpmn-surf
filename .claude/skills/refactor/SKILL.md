# Рефакторинг

## Можно
- Улучшать структуру, именование, разделение ответственности
- Выделять классы из плоского кода (по образцу: файл-классы differ-страницы, `master-commit-manager.js`)
- Уменьшать дупликацию, упрощать логику
- Небольшие сфокусированные улучшения

## Требования
- Поведение сохраняется **точно**; публичный UI и пользовательский поток не меняются. Сохранять даже наблюдаемые мелочи (тексты логов, опечатки в UI) — их правка обсуждается отдельно
- One concern per change; маленькие diff'ы; не смешивать с фичами
- ⚠️ Глобальные переменные и функции видны между скриптами одного scope'а. Scope'ов два: content scripts GitLab-страницы (порядок в `manifest.json`) и страница differ'а (порядок в `utils.js#loadScripts`: utils → файлы-классы → bpmn-differ → dmn-differ). Перед переименованием/переносом найди ВСЕ использования через Grep по всем js-файлам
- ⚠️ Общие классы differ-страницы (`DifferParams`, `DiagramVersions`, `BranchIndicator`, `DiffType`) используют и `bpmn-differ.js`, и `dmn-differ.js` — меняя их API, правь обоих потребителей. Глобального изменяемого состояния на differ-странице быть не должно — состояние только в полях классов
- `libs/` и порядок `content_scripts` — не трогать. `manifest.json` (`web_accessible_resources`) и `utils.js#loadScripts` менять можно **по согласованию с пользователем** — это типовой шаг при выносе кода в новый файл
- Новый файл differ-страницы = запись в `utils.js#loadScripts` (до `bpmn-differ.js`) + в `web_accessible_resources` манифеста. Top-level `let`/`const`/`class` не должны конфликтовать с именами в других скриптах scope'а (redeclaration = SyntaxError); в статических полях классов не ссылаться на глобалы, объявленные в позже загружаемых файлах

## Workflow
1. Объясни, что и зачем рефакторить, опиши trade-offs
2. Предложи план с файлами и изменениями; ключевые развилки (структура файлов, охват) — через вопросы пользователю
3. Дождись подтверждения перед структурными изменениями
4. Применяй инкрементально
5. Проверь, что поведение не изменилось

## Проверка после рефакторинга
1. `node --check` по всем изменённым/новым js-файлам; `manifest.json` — валидный JSON; `npm test` — юнит-тесты зелёные (тесты фиксируют текущее поведение — падение теста при рефакторинге означает изменение поведения)
2. Grep по удалённым/переименованным именам во ВСЕХ js-файлах — висячих ссылок нет (особенно из `dmn-differ.js`)
3. Запусти субагента `code-reviewer` с акцентом на построчную сверку со старой версией (`git show HEAD:<file>`)
4. Актуализируй инструкции: `docs/architecture.md` (архитектура, таблица ключевых файлов), `docs/conventions.md` (ограничения), CLAUDE.md и `.claude/agents/`, `.claude/skills/` — Grep по `.claude/`, `docs/` и CLAUDE.md на упоминания изменённых имён/структуры
5. Напомни пользователю ручной чеклист из `docs/testing.md` (включая DMN-diff — общие классы differ-страницы)

Если поведение может измениться: остановись, объясни риск, запроси подтверждение. Избегай overengineering — простота > абстракции.
