# Новая фича

## Workflow
1. **Уточнение** — если критичная информация отсутствует, задай вопросы; предложи варианты, если есть выбор
2. **План** — шаги, затронутые файлы, архитектура решения, риски (включая возможную правку `manifest.json` для permissions)
3. **Подтверждение** — для сложных изменений не начинай без подтверждения плана
4. **Реализация** — по плану, минимальные изменения, стиль из `docs/conventions.md`
5. **Верификация** — фича работает, существующее поведение не сломано; запусти `npm test`; новую изолированную логику differ-страницы покрой юнит-тестами (харнесс `test/support/scope.js`, см. `docs/testing.md`)
6. **Учёт задачи** — если работа относится к задаче из `docs/issues/` (или это новая задача): обнови её файл по правилам `docs/issues/README.md` — добавь запись в «Историю работы» (модель · дата · коммит/ветка + что сделано) и выстави `status` (`done`/`partial`/`in-progress`); при `done` — перенеси файл в `docs/issues/archive/features/` (`git mv`). Нет файла, но фича тянет на отдельную задачу — заведи новый файл в `docs/issues/features/`

## Правила
- Следуй существующей архитектуре: провайдеры (`*-repo-provider.js`), differ'ы, утилиты из `utils.js` — переиспользуй, не дублируй
- Новый UI — через `GitLabUIRepoProvider` (инъекция кнопок) и `styles.css`
- Не трогай `libs/` руками (генерируется `npm run sync:libs`), не добавляй зависимости, не вводи build-шаг
- `manifest.json` менять только если без этого нельзя, с явным указанием в плане и согласованием
- Помни про общий global scope: новый content script добавляется в правильное место порядка `content_scripts`; новый файл страницы differ'а — в `utils.js#loadScripts` (до `bpmn-differ.js`) И в `web_accessible_resources`
- Фичи differ-страницы клади в подходящий файл-класс (params, versions, view, comparator, highlighter, viewport, changes-table и т.д.), а не в оркестраторы `bpmn-differ.js`/`dmn-differ.js`; учитывай общие классы bpmn↔dmn (см. `docs/architecture.md`)
- Новый файл или изменение архитектуры → актуализируй `docs/architecture.md` (таблица ключевых файлов), при необходимости CLAUDE.md и инструкции в `.claude/agents/`, `.claude/skills/`
