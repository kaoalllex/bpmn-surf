# New feature

## Workflow
If a spec/plan for this task already exists in `docs/superpowers/` (from `brainstorming`/`writing-plans`), it covers steps 1–3: start at step 4.

1. **Clarification** — if critical information is missing, ask questions; propose options when there is a choice
2. **Plan** — steps, affected files, solution architecture, risks (including a possible `manifest.json` edit for permissions)
3. **Confirmation** — for complex changes, do not start without confirming the plan
4. **Implementation** — per the plan, minimal changes, style from `docs/conventions.md`
5. **Verification** — the feature works, existing behavior is not broken; run `npm test` (it also parses every `src/` script) and the affected e2e specs; check the twin paths (CLAUDE.md); page decoration / navigation / edit-mode changes → the `live-check` skill; cover new isolated differ-page logic with unit tests (harness `test/support/scope.js`, see `docs/testing.md`); a non-trivial diff → the `code-reviewer` subagent before `/pr`
6. **Task tracking** — if the work relates to a task in `docs/issues/` or deserves one: update or create its file per `docs/issues/README.md`

## Rules
- Follow the existing architecture: providers (`*-repo-provider.js`), differs, helpers from `utils.js` — reuse, do not duplicate
- New page UI — via the platform's UI provider (`gitlab-ui-repo-provider.js` / `github-ui-repo-provider.js`, button injection) and `content-styles.css`; differ-page UI — `src/differ/styles.css`
- Do not touch `libs/` by hand (generated by `npm run sync:libs`), do not add dependencies, do not introduce a build step
- `manifest.json` composition (resources) is edited freely; new permissions or hosts only with an explicit note in the plan and approval
- Remember the shared global scope: a new content script is added at the right place in the `src/hosts/content-scripts.json` order (and to `test/support/scope.js#SCOPE_FILES`); a new differ-page file — to `utils.js#loadScripts` (before `bpmn-differ.js`) AND to `web_accessible_resources`
- Put differ-page features in the appropriate class file (params, versions, view, comparator, highlighter, viewport, changes-table, etc.), not in the orchestrators `bpmn-differ.js`/`dmn-differ.js`; account for the shared bpmn↔dmn classes (see `docs/architecture.md`)
- A new file or an architecture change → update `docs/architecture.md` / the area file in `docs/architecture/`, and if needed CLAUDE.md and `.claude/`
