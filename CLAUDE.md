# CLAUDE.md — BPMN Diff for GitLab

Chrome Extension (Manifest V3) для визуального сравнения BPMN 2.0 и DMN диаграмм в GitLab merge requests и репозиториях. Vanilla JavaScript (ES6+), без фреймворков, бандлеров и build-шага. Наш GitLab: https://gitlab.example.com.

## Язык ответов

Всегда отвечай на **русском**, независимо от языка запроса (если пользователь явно не попросил другой язык). Код, команды, пути, логи, идентификаторы и цитаты не переводить.

## Критичные правила (кратко; полные списки — в docs/)

- ⚠️ `libs/` — внешние библиотеки, **НЕ изменять вручную**; генерируются `npm run sync:libs` из версий в `package.json` (см. `docs/conventions.md`)
- ⚠️ **master protected** — никогда не коммитить/пушить в master; работа только в своей feature-ветке. Завершение задачи = push ветки + MR **без отдельного разрешения** (после зелёных тестов); мерж MR — только пользователь. Локальная уборка ветки — по команде «прибраться»/«закончить» уже после мержа (см. `docs/git-workflow.md`)
- ⚠️ Перед каждым push — **`npm test`**; с падающими тестами не пушить
- ⚠️ Порядок загрузки скриптов важен (зависимости): `content_scripts` в `manifest.json` и `utils.js#loadScripts` — не переставлять без необходимости. Сам состав `manifest.json` (добавить/убрать ресурс) правится свободно
- ⚠️ Только vanilla JS (ES6+), без новых runtime-зависимостей; dev-зависимости — только по согласованию
- ⚠️ Общие классы differ-страницы используют и BPMN-, и DMN-differ — меняя их, проверяй оба
- ⚠️ Если пользователь просит **придумать/предложить что-то самому** — сперва покажи предложение и дождись подтверждения
- ⚠️ После изменений архитектуры/файлов/процессов — актуализировать CLAUDE.md, `docs/*.md` и `.claude/` (правило — в `docs/conventions.md`)

Если изменение грозит **неожиданным или вне-scope** изменением поведения: остановись, объясни риск, запроси подтверждение. Изменения поведения в рамках самой задачи — нормальный ход работы.
