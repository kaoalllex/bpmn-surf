# CLAUDE.md — bpmn-surf

Chrome Extension (Manifest V3) for browsing and comparing BPMN 2.0 and DMN diagrams in GitLab merge requests and repositories. Vanilla JavaScript (ES6+), no frameworks, bundlers, or build step. The repository itself is **local-only** right now — the old GitLab remote (`gitlab.example.com`) is unreachable and a move to public GitHub is planned ([INFRA-0007]); see `docs/git-workflow.md`. (GitLab still matters as the platform the extension *works on* — that is unrelated to where the sources live.)

(The product is branded `bpmn-surf`; internal identifiers, code paths, the git repo and the project folder still use the historical `bpmn-diff` name — the repo/folder rename is deferred to area B, see [INFRA-0007].)

## Workflow

Multi-step work follows the Superpowers flow: `brainstorming` → `writing-plans` → `executing-plans`. Plans live in `docs/superpowers/plans/`, specs and designs in `docs/superpowers/specs/`. Implementation and git steps inside that flow are carried out by the project skills: `feature`/`fix`/`refactor`; the git-publishing steps (`/mr`, then `/cleanup` after the human merges) are on hold while the repository has no reachable remote — work stops at local commits. Each skill's trigger conditions live in its own `description` (`.claude/skills/`, `.claude/commands/`; surfaced in the CLI via `/`) — not duplicated here.

## Critical rules (brief; full lists — in docs/)

- ⚠️ `libs/` — external libraries, **do NOT change manually**; generated by `npm run sync:libs` from the versions in `package.json` (see `docs/conventions.md`)
- ⚠️ **master protected** — never commit into master, even locally; work only in your own feature branch, branched off the **local** master. **No remote:** GitLab is gone, GitHub is planned — completing a task = green tests + local commits on the branch, **no push, no MR, no `/mr` / `/cleanup`** (see `docs/git-workflow.md`)
- ⚠️ Before declaring a task done (and before any future push) — **`npm test`**; never report work as finished with failing tests
- ⚠️ Script load order matters (dependencies): `content_scripts` in `manifest.json` and `utils.js#loadScripts` — do not reorder unnecessarily. The composition of `manifest.json` itself (add/remove a resource) is edited freely
- ⚠️ Only vanilla JS (ES6+), no new runtime dependencies; dev dependencies — only by agreement
- ⚠️ MCP servers — **local only** (stdio, run on the machine); connecting external/remote MCP (URL/SSE/HTTP) is forbidden
- ⚠️ The shared differ-page classes are used by both the BPMN and DMN differ — when changing them, check both
- ⚠️ If the user asks you to **come up with / propose something yourself** — first show the proposal and wait for confirmation
- ⚠️ After changes to architecture/files/processes — update CLAUDE.md, `docs/*.md`, and `.claude/` (the rule — in `docs/conventions.md`)

If a change risks an **unexpected or out-of-scope** behavior change: stop, explain the risk, request confirmation. Behavior changes within the task itself are a normal part of the work.
