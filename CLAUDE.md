# CLAUDE.md — bpmn-surf

Chrome Extension (Manifest V3) for browsing and comparing BPMN 2.0 and DMN diagrams in GitLab merge requests and repositories. Vanilla JavaScript (ES6+), no frameworks, bundlers, or build step. The sources live on public GitHub: `https://github.com/kaoalllex/bpmn-surf`; see `docs/git-workflow.md`. (GitLab still matters as the platform the extension *works on* — that is unrelated to where the sources live.)

(The product is branded `bpmn-surf`; internal identifiers, code paths and the local project folder still use the historical `bpmn-diff` name.)

## Response language

Respond in the language the user opens the conversation with (the language of their first message in the session), unless they explicitly ask for another language. Do not translate code, commands, paths, logs, identifiers, or quotes. All documentation and code comments are in English only.

Do your internal reasoning (thinking) in **English** regardless of the conversation language — it keeps reasoning token-efficient with no loss of quality. This applies only to the reasoning; the final answer to the user follows the rule above.

## Workflow

Multi-step work follows the Superpowers flow: `brainstorming` → `writing-plans` → `executing-plans`. Plans, specs and designs live in `docs/superpowers/` — **local only, not tracked by git**: they are working artifacts for the duration of a task, not a record. Whatever is worth keeping moves out before the task closes — into `docs/` if it describes the system as shipped, or into the task file in `docs/issues/` if it describes work still to be done; git history covers the rest. Implementation and git steps inside that flow are carried out by the project skills: `feature`/`fix`/`refactor`; publishing means pushing the branch and opening a PR on GitHub (`/pr`, then `/cleanup` once it is merged). Each skill's trigger conditions live in its own `description` (`.claude/skills/`, `.claude/commands/`; surfaced in the CLI via `/`) — not duplicated here.

## Critical rules (brief; full lists — in docs/)

- ⚠️ `libs/` — external libraries, **do NOT change manually**; generated by `npm run sync:libs` from the versions in `package.json` (see `docs/conventions.md`)
- ⚠️ **master protected** — never commit into master; work only in your own feature branch, branched off master. Completing a task = green tests + commits on that branch, pushed to GitHub with a PR into master (see `docs/git-workflow.md`)
- ⚠️ Before declaring a task done (and before any push) — **`npm test`**; never report work as finished with failing tests
- ⚠️ Script load order matters (dependencies): `content_scripts` in `manifest.json` and `utils.js#loadScripts` — do not reorder unnecessarily. The composition of `manifest.json` itself (add/remove a resource) is edited freely
- ⚠️ Only vanilla JS (ES6+), no new runtime dependencies; dev dependencies — only by agreement
- ⚠️ MCP servers — **local only** (stdio, run on the machine); connecting external/remote MCP (URL/SSE/HTTP) is forbidden
- ⚠️ The shared differ-page classes are used by both the BPMN and DMN differ — when changing them, check both
- ⚠️ If the user asks you to **come up with / propose something yourself** — first show the proposal and wait for confirmation
- ⚠️ After changes to architecture/files/processes — update CLAUDE.md, `docs/*.md`, and `.claude/` (the rule — in `docs/conventions.md`)

If a change risks an **unexpected or out-of-scope** behavior change: stop, explain the risk, request confirmation. Behavior changes within the task itself are a normal part of the work.
